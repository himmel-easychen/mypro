# 生成、审查与交付模式

目标：根据招标结构、有效企业事实和用户决定生成可追溯的响应文件。用户可以请求完整稿、单一章节、修改已有稿或仅输出目录；门槛和检查范围与请求保持一致。

## 1. 组装写作输入

主控汇总目标章节、招标规定结构、对应要求与评分项、证据片段、有效决定、写作限制和待决项。形成“生成输入包”，仅包含本次写作需要的内容。冻结当前有效的项目名称、主体、金额、日期、工期、人员和服务指标，供所有章节共用。

不存在原始模板时，按已知提交结构形成草案；不能声称它是招标方指定模板。用户要求带缺口草稿时，把未决字段显式纳入写作包。

## 2. 按章节类型处理

| 章节类型 | 写作方式 |
|---|---|
| 固定表格与声明 | 保留招标方规定的结构和必要文字，仅填入已知字段；待签章处保持待办理状态 |
| 企业资质、业绩、人员 | 依据真实证明填充，绑定证据位置；缺失时列出需补项 |
| 技术方案、服务方案 | 按“要求—执行措施—责任/资源—验收或证明方式”回应，内容应具体到本项目 |
| 报价与计算表 | 使用确认的单价、数量、税率、币种和舍入规则；宿主有计算工具时实际复算 |
| 工期、SLA、质保等承诺 | 使用用户有效决定；可以提出建议指标供协作，但不直接把建议写成已授权承诺 |

支持子 Agent 时，每位章节作者只处理指定范围并返回草稿、引用、覆盖的要求和未决项。主控统一术语和全局参数，合并后再进行跨章节审查。

## 3. 审查

审查员取得原始要求、证据和有效决定，逐项检查：

- **覆盖**：每个范围内的强制要求是否有响应，评分点是否按规则得到支撑。
- **真实性**：企业主张是否有证明或明确的用户说明，参考材料有没有混入当前事实。
- **一致性**：金额、税率、数量、项目名称、时间、人员和承诺在各章节及附件中是否一致。
- **完整性**：是否遗漏强制表格、附件、签章要求，是否还存在必填占位、空章、重复章节。
- **计算**：可复算的汇总、分项、税额和分值是否一致；无法计算的项标记未核验。
- **格式**：目标交付格式、目录、编号、页数/字数约束和固定模板是否得到满足。

每个问题有章节位置、证据或规则、影响、修订建议及是否阻塞交付。把问题交回相应写作者；修订后复核修改内容和受其影响的全局一致性。工具或材料不足导致的问题进入交付说明，不通过重复自评将其消除。

## 4. 使用宿主生成文件

宿主支持文档/表格生成时，按其实际工具说明创建目标文件，再用可用的预览或渲染能力检查文件。只能生成正文时，交付有结构的可复制稿并说明文件格式仍待处理。

外部引用和内部证据检查索引可以放在单独的审查附件中。投标正文的引用形式服从招标方格式要求，不把 Agent 内部角色记录或工具日志混入正文。

## 5. 最终交接

给出交付文件或正文、完成范围、材料/决定版本、剩余问题、待办理签章/附件及实际完成的检查。标题明确区分草稿、带缺口草稿和完成审查的版本。未验证排版时如实说明；文件导出成功也不能自动代表投递资格与全部格式已审查通过。
