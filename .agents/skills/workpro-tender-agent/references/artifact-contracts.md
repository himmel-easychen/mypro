# 产物与状态约定

这些字段用于不同角色、不同会话之间稳定交接。按任务需要创建产物，不要求每次都填写全部表格。默认以用户可读的 Markdown 或宿主文档保存；宿主方便处理结构化数据时也可以使用 JSON。

## 工作记录

- 项目与目标：项目名、标段/范围、用户要的交付物。
- 能力路径：宿主已验证的阅读、搜索、计算、写作、导出和委派能力，以及限制。
- 当前进度：当前模式、完成范围、尚未读取的材料和待办。
- 材料：资料目录及版本关系。
- 产物：ID、类型、版本、来源、有效状态。
- 决策：当前有效决定及被替代的旧决定。
- 问题：未决事实、商业决定、审查问题和阻塞原因。
- 下一步：下一角色、任务和所需输入。

继续旧会话时先对齐目标、材料版本和有效决定。仅有一段摘要时说明其证据范围，必要时重新打开来源核对关键内容。

## ID 与公共字段

资料可用 DOC-001，证据用 E-001，要求用 R-001，评分用 S-001，决策用 D-001，章节用 SEC-001，问题用 I-001。编号只是便于引用的内部标识，不是系统数据库或真实文件页码。保留既有编号，新增内容递增即可。

产物公共字段：ID、类型、版本、依据的材料/决定版本、状态、内容、来源、未决项、被替代版本及原因。更新时保留变更摘要；这种宿主工作记录不等于具备不可篡改的审计系统。

## 材料目录与证据

材料目录记录：文件名、资料 ID、业务角色、日期/版本、实际读取范围、识别问题、存储/会话范围、与其他版本的关系。

证据记录：证据 ID、资料 ID、真实位置、原文或准确摘要、能支撑的主张/要求、有效日期与适用主体、识别限制。用户说明的事实单列来源为“用户说明”，不要伪装为附件证明。

## 要求、评分与风险

| 产物 | 必要字段 |
|---|---|
| 项目摘要 | 项目/标段、采购范围、关键日期、资格条件、文件结构、来源、未知项 |
| 要求矩阵 | 要求 ID、内容、类别、强制性、来源、企业响应状态、证据 ID、缺口 |
| 评分矩阵 | 评分 ID、规则、分值/上限、证明要求、对应证据、可得分判断、假设/未知项 |
| 提交结构 | 卷册/章节、固定表格、附件、签章、格式/份数、提交方式、来源 |
| 报价规则 | 数量、单位、币种、税口径、费用范围、计分或汇总规则、来源 |
| 风险/缺口 | 问题 ID、影响要求、来源、后果、严重程度、可行措施、责任方、状态 |
| 策略比较 | 方案、依据、取分条件、工作量/资源、承诺、主要风险、待确认内容 |

## 决策记录

记录问题、上下文、实际可行选项、用户明确选择、确认依据、适用范围、影响的产物/章节、状态和被替代关系。状态为待决定、有效、被替代或撤回。

将企业事实核验与商业决定分别记录：用户决定采用某方案，不代表该方案所需的资质证明已经存在。

## 生成输入包与章节交接

生成输入包包含：本次交付范围、目录/模板、对应要求与评分、已确认企业内容、证据、有效决定、统一全局参数、仍存在的缺口、草稿或最终稿要求。

每章交接包含：章节 ID、目标、内容类型、输入证据与决定、覆盖要求、正文、引用映射、未决项、版本。作者改变全局参数前交回主控处理，不能局部改出另一套价格或承诺。

## 审查与交付

审查问题记录：问题 ID、章节位置、具体问题、依据、影响、修订建议、是否阻塞、修订状态。记录实际使用的检查方式：独立子 Agent 复核、同一 Agent 按角色复查、计算工具复算或文件渲染检查。

交付记录包含：产物版本、交付范围、实际文件或正文、已完成检查、剩余问题和必要的人工办理事项。无文件工具时输出一份可复制的状态摘要，便于用户在另一会话继续。
