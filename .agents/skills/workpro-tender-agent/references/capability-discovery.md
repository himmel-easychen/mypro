# 宿主能力发现

目的：把业务步骤映射到当前 Agent 真正能调用的能力，形成可执行路径。读取宿主当前公开的工具说明、附件访问方式和既有使用结果。按任务需要检查，不按工具品牌或模型名称猜测能力。

## 检查方式

1. 明确本次交付范围：解释条款、分析材料、形成投标策略、编写章节，或交付完整文件。
2. 从当前可用工具说明中找出所需能力，记录实际工具名称、支持的输入、输出和限制。若宿主提供能力发现入口，使用该入口；无入口时以当前公开工具列表为准。
3. 用用户任务中的一个实际步骤验证必要能力，例如读取已上传文件的一页或搜索一条明确条款。成功结果才是可用证据。已有本会话成功结果可以复用。
4. 将状态标为“已验证”“已发现但未验证”“不可用”“未知”，并给出替代路径。未知与不可用不能混写。
5. 当工具不可用时，只降级受影响环节。不要为执行此技能要求安装 WorkPro，也不要把部署服务作为前置步骤。

## 业务到工具的映射

| 所需工作 | 优先发现的宿主能力 | 替代路径与限制 |
|---|---|---|
| 读取 PDF、Word | 附件阅读、PDF/Word 解析 | 请求可读文本或按文件分批处理；缺页显式记录 |
| 扫描件识别 | 原生视觉阅读、OCR | 仅将能看清的内容作为证据；复杂表格识别不可靠时要求清晰页面 |
| Excel 和报价表 | 表格读取、计算工具、代码执行 | 阅读可见表格；无法复算公式时标注“尚未复算” |
| 大量材料中的证据查找 | 文件搜索、知识库、附件检索 | 建立章节/文件索引，按问题定位原文；不宣称已建立向量库 |
| 生成有依据的答案 | 宿主写作能力加证据检索 | 分批提供原文片段和来源，按证据回答；不能用自由发挥填缺口 |
| 多角色工作 | 子 Agent、任务委派 | 单 Agent 顺序执行相同角色职责，报告复核方式 |
| DOCX/XLSX/PDF | 宿主文档、表格、文件导出工具 | 返回可复制正文或结构化表格，说明尚未生成目标格式文件 |
| 排版检查 | 文档预览、PDF渲染、图像检查 | 仅报告文字内容检查，不宣称验证了分页和版式 |
| 持续协作 | 宿主工作空间、项目记忆、文件存储 | 输出可保存交接摘要，下一会话由用户带入 |

宿主内置文件搜索能够提供带定位的证据时，可直接服务于检索增强问答。Agent 无须先取得其底层向量库地址、Embedding 模型或 API Key。只有用户明确选择自配检索工具时，才按该工具公开的配置要求检查账户和授权状态；使用宿主配置界面或托管凭据，不读取或输出密钥值。

## 最小能力报告

向用户展示任务相关的表格：步骤、状态、实际依据、替代方案、对交付的影响。工具内部参数保留在工作记录中。

例：文件阅读已验证；附件搜索已验证；DOCX 导出不可用。因此可以完成条款分析和正文草稿，交付形式为可复制文稿，不能称已导出 Word。

## 何时重新检查

新增文件格式、切换工作环境、工具返回权限/格式错误或用户要求新的交付格式时，复查相关能力。不要每轮对话重新做全套自检，也不要将“会话还能聊天”当作其他工具全部可用。
