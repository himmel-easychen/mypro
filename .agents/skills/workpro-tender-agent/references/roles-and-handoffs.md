# 角色、分工与交接

这些角色是可迁移的工作职责。宿主是否提供子 Agent，决定实际执行方式。不要为了使用角色架构而要求安装插件或创建额外 Agent。

## 职责边界

| 角色 | 接收 | 负责输出 | 不自行决定的事项 |
|---|---|---|---|
| 主控 | 用户目标、工作记录、各角色结果 | 任务分解、模式路由、结果合并、冲突处理、用户答复 | 缺乏用户依据的商业承诺 |
| 资料员 | 新附件、已有索引 | 文件目录、提取内容、来源定位、版本关系、识别问题 | 将历史参考升级为当前事实 |
| 招标分析员 | 招标材料及补遗 | 要求矩阵、评分矩阵、提交结构、报价规则、否决风险 | 未给出的企业能力和价格 |
| 证据核验员 | 要求矩阵、企业材料 | 要求与证据绑定、有效性检查、缺口清单 | 仅凭用户意愿判定证明有效 |
| 策略协作员 | 分析结果、缺口、用户偏好 | 策略比较、协作议题、决策记录、生成准备状态 | 代用户选择报价和保证 |
| 章节写作者 | 章节任务包、确认内容和证据 | 指定章节草稿、来源映射、待决问题 | 擅自修改价格/工期/范围等全局参数 |
| 审查员 | 原始要求、证据、有效决策、草稿 | 可定位的问题及阻塞判断、修订建议 | 仅依据作者自评判定通过 |
| 交付整理员 | 审查通过的内容和文件格式要求 | 宿主可生成的文件、版式检查结果、交付清单 | 将未核查草稿称为可直接投递文件 |

## 真正子 Agent 可用时

独立的材料读取、不同要求类别提取，以及输入冻结后的不同章节写作，可以并行。证据匹配依赖要求矩阵，策略评估依赖证据覆盖，最终写作依赖有效决策，因此先完成这些依赖再派发。审查角色尽可能使用独立上下文，并取得原始依据，而不只是作者的摘要。

主控保留全局参数和唯一有效决策表。分派章节或文件的明确范围，避免两个角色同时覆盖同一交付文件；由主控合并。结果冲突时返回原文或向用户询问相应决策，不按多数意见决定事实。

## 单 Agent 执行时

按相同依赖顺序执行角色阶段，把提取结果、用户决定和生成稿区分保存。审查阶段重新对照原始要求与证据，避免只润色刚写的文字。可以报告“按审查清单自检”，不能声称已获得独立 Agent 验证。

## 可直接复用的派发格式

```text
角色：{角色名}
任务：{具体业务结果及边界}
输入：{资料/产物 ID 和可访问内容或位置}
有效决定：{本任务需要遵守的已确认决定及全局参数}
能力：{宿主当前允许使用的实际工具}
输出：{应提交的产物及字段，来源定位，未决问题}
验收：{必须覆盖的要求、证据或质量标准}
遇到缺口：继续可完成部分；返回受阻项及所需输入，不编造事实。
```

## 主控的结果验收

检查输入版本是否正确、任务范围是否完成、来源能否定位、事实与推断是否分开、未决项是否遗漏，以及是否越权形成了商业决定。未通过时将具体问题交回相应角色修订，不以一句“重新检查”代替明确反馈。

一次审查后针对问题修订，再复核受影响部分。若同一问题因缺少工具、资料或用户决定持续存在，保留阻塞原因并交付其余成果，避免无依据循环重写。
