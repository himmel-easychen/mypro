# 协作模式

目标：把分析阶段的缺口、策略和承诺问题转化为可用于写作的有效决定。输入包括要求与评分矩阵、证据覆盖、风险、候选方案和用户已有决定。

## 协作议题排序

先处理资格/否决风险、范围与标段、截止时间等决定可行性的事项，再处理高权重得分、证明材料、报价、人员/交付资源和承诺，最后处理可逆的表达与排版选择。只有阻碍当前结果的问题才需要立即询问，其余工作继续推进。

每个议题用以下结构呈现：

1. 需要决定什么，为什么影响本次交付。
2. 已知事实和来源；缺失或相互冲突的内容。
3. 实际可行的选项，以及每项的取分、成本、材料、时间和风险影响。
4. 有依据时提出建议并说明条件；请求用户给出明确决定或补充事实。

一次集中处理相关问题，避免用户被琐碎确认打断。用户在前文已明确的选择应记为有效决定，不重复要求批准同一件事。

## 三类记忆

| 类别 | 内容 | 能否直接用于当前标书 |
|---|---|---|
| 参考材料 | 历史标书、行业示例、旧项目讨论 | 只能帮助组织结构和提出问题，当前事实需重新确认 |
| 临时设想 | 尚在比较的方案、待核实的口头信息 | 只能进入假设或草稿占位 |
| 有效决定 | 用户对当前项目明确作出的范围、策略、报价或承诺选择 | 可以用于对应章节，仍需区分用户决定与客观证明 |

确认“我们会提供该服务”不会自动证明“我们已有该资质”。接受风险也不会使一项明确不符合的招标条件变成符合。

## 决策变更

给决定稳定编号，记录决定内容、适用范围、确认依据及影响的章节。用户修改决定时，将旧记录标为被替代，并更新全局参数和下游产物；无法确定是否撤回旧决定时，只询问冲突部分。

新材料可能消除缺口，也可能推翻旧判断。先更新证据覆盖和风险，再调整策略；不要只把新材料追加在文末。

## 生成准备判断

针对用户请求的章节或完整稿检查：

- 范围和响应目录可确定，强制表格/格式可获取。
- 相关要求已分析，所需企业事实与证明有明确来源。
- 价格、税口径、人员、工期、服务指标等相关承诺已明确，或本章节确实不涉及。
- 必填缺口已解决；仍有问题时能清楚划出受影响内容。

以“可生成指定范围”“可生成带缺口草稿”“需补关键输入”交付准备结论，并列出原因。用户已经要求写作且输入齐备时直接进入生成。草稿中的未决事项保持可见，不能在生成过程中悄悄补成事实。
